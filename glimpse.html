glimpse. — micro-journal

One entry. Every day. Forever. A minimal micro-journal for iOS and Android — no word counts, no prompts you have to follow, just one entry a day. Built solo in Flutter, local-only, with an optional AI-generated reflection on the themes running through your entries. Part of Orbit, a suite of three minimal daily-habit apps sharing one design language.

Flutter & Dart · Solo developer · Aug 2025 – present

What it does

  • One entry a day, with 10 rotating writing prompts to spark a thought — no pressure beyond that.
  • Streak tracking, a scrollable entry history, a calendar view marked with every day written, and edit-anytime on past entries.
  • Reveal glimpse: an on-demand call to Google's Gemini API that reads a month's unsummarized entries and generates a short reflection on the themes running through them.
  • Everything persisted locally in a real database — no account, nothing leaves the device except the optional reveal call.

Engineering highlights

  • Migrated the data layer live, without losing anyone's entries. glimpse. started on shared_preferences and moved to a versioned SQLite schema (sqflite) with onCreate/onUpgrade migrations. A one-time migration path reads the legacy JSON blob, batch-inserts every entry into the new database, and sets a boolean flag so the import never re-runs on a later launch — verified by seeding legacy data, running the upgrade, and confirming a second launch was a no-op.
  • Enforced one-entry-per-day at the storage level, not just in the UI: entries upsert via ConflictAlgorithm.replace on a date-keyed primary key, so writing twice for the same day always resolves to a single row. Journaling streaks are computed by walking backward through an in-memory date map.
  • Guarded the Gemini integration against runaway usage. A self-imposed monthly cap — well under any plausible free-tier quota — is tracked in local storage with a month-keyed counter, so a stray double-tap or bug can't run up real API usage. The cap resets automatically at the start of each calendar month.
  • Design system: a warm editorial dark theme (matched light/dark palettes, Georgia serif for entry text), a duotone image-filter pipeline (a luminance-mapped ColorFilter matrix) for entry photos, and a hand-rolled CustomPainter loading animation.

Testing & verification

Solo developer, no dedicated QA — verified manually during development, before each merge:

  • Smoke-tested every feature on iOS Simulator and Android Emulator before merging, across both light and dark themes.
  • Verified the shared_preferences→SQLite migration by seeding legacy JSON data, running the upgrade path, and confirming every entry landed exactly once with no duplicates or loss.
  • Ran flutter analyze (flutter_lints) as a static-analysis gate. Next up: real unit tests around the migration and upsert logic, since both are already pure functions with no UI dependency.
