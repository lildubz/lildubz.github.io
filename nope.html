nope. — habit-resistance tracker

A cross-platform mobile app that helps users resist impulses and build positive habits through daily engagement, streaks, and adaptive feedback. Built solo in Flutter, offline-first, currently in beta. Part of Orbit, a suite of three minimal daily-habit apps sharing one design language.

Flutter & Dart · Solo developer · Aug 2025 – present

What it does

  • Tap "NOPE" once per day per habit to log a resisted urge and grow that habit's streak, with automatic streak resets on a missed day.
  • Four selectable feedback tone packs (Light / Dark / Dry / Savage) that adjust motivational messaging based on real-time streak length.
  • Custom habit colors and icons, a calendar view of resisted urges, confetti on completion, and a rolling log of recent urges per habit.
  • App-lock security: an optional 4-digit passcode with Face ID / Touch ID unlock, so the app can hold something a user doesn't want casually opened.
  • Daily local reminders nudging users before a streak lapses.
  • Fully offline — everything persists on-device via shared_preferences.

Engineering highlights

  • Fixed a full-list re-render bottleneck. Tapping one habit's streak button was triggering a rebuild of the entire habit list. I refactored the Habit model to extend ChangeNotifier and wrapped each list item in AnimatedBuilder + RepaintBoundary, isolating rebuilds to the widget that actually changed — no external state-management library needed.
  • Modeled streak continuity as an explicit set of edge cases rather than a running counter: date-only comparisons dedupe a second tap on the same day, a skipped calendar day zeroes the streak, and the longest-streak high-water mark is tracked independently so it survives a reset. Destructive resets sit behind a two-step confirmation gate.
  • App-lock security hashes the 4-digit passcode with SHA-256 before it ever touches storage — the raw code is never persisted — with biometric unlock via local_auth and automatic re-lock on app resume (via a WidgetsBindingObserver), so backgrounding the app doesn't leave it open.
  • Local notification scheduling (flutter_local_notifications + timezone) reminds users before a streak lapses, handled across time zones correctly.

Testing & verification

Solo developer, no dedicated QA — verified manually during development, before each merge:

  • Smoke-tested every feature on iOS Simulator and Android Emulator before merging, across both light and dark themes.
  • Manually tested the app-lock flow end-to-end: passcode set / verify / change, biometric enrollment on and off, forced re-lock on app resume, and lockout behavior on a wrong passcode.
  • Ran flutter analyze (flutter_lints) as a static-analysis gate. The next step is backing the streak logic — already pure, UI-independent functions — with real unit tests.
